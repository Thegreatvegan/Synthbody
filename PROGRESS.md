# Capability expansion — progress and blockers

Status of the ten-module expansion toward Simcyp/GastroPlus-class capability.
Written to be useful to whoever picks this up next, which includes being blunt
about what is not done and why.

**Branch** `feature/pbpk-expansion` · **Baseline** `3d0d122` (234 tests)
· **Current** 286 tests passing

The governing rule for everything below: *a module is not finished when it
runs, it is finished when its output has been checked against something that
was not used to build it.* Several modules in this list are blocked not on
engineering but on obtainable data, and those are marked as such rather than
built on invented inputs.

### Audit finding: the absorption model was unreachable

The seven-compartment CAT/ACAT model shipped working, tested and benchmarked,
but was never registered in `model_specs()`. The frontend reads the registry
rather than hard-coding model knowledge, so the model could not be selected in
Studio and was reachable only through the three benchmark endpoints.
Capability the UI cannot reach is not capability. Fixed, and pinned by
`test_both_absorption_models_are_registered`.

A second, cosmetic finding: `README.md` quoted "199 tests" in its architecture
tree while the suite had 234. Corrected.

### Baseline protection

- `backend/tests/baseline/reference_outputs.json` — every shipped model's full
  concentration curve, both validation results, all twelve partition
  coefficients and the theophylline benchmark, frozen at `3d0d122`.
- `backend/tests/test_baseline_regression.py` — 9 tests that replay all of it
  at `rtol=1e-9`.

Reference numbers in this repository are **generated by running the code**, never
typed in by hand. During this work a hand-typed expected value was caught being
wrong in the fifth decimal place, which is exactly the failure mode the
generated-fixture rule exists to prevent.

> **If a baseline test fails,** the fix is to revert the change or document why
> the result moved. Regenerating the fixture to make it pass destroys its only
> purpose.

## P1 — Whole-body PBPK ✅ built and clinically tested

The largest piece of this expansion, and the only module whose validation gate
has actually been cleared.

### What was built

`backend/synthbody/engine/models/oral_pbpk.py` — the seven-compartment ACAT
lumen model coupled to the twelve-tissue perfusion-limited distribution model.

**Built by delegation, not duplication.** Both parents are held as instances
and both `rhs` methods are *called*. The coupled model therefore cannot drift
from the equations the existing validated and benchmarked results were produced
with, and `test_absorption_rhs_is_delegated_not_reimplemented` compares the
lumen derivatives against the standalone model at `atol=0`.

**What is scientifically new:** absorbed drug enters the **gut tissue
compartment**, which drains through the portal vein into the liver.

```
lumen --absorption--> gut tissue --portal--> liver --> systemic circulation
```

The standalone PBPK model empties its oral depot straight into the liver, and
`OralAbsorptionWithDisposition` applies first pass as two empirical scalars
`f_gut` and `f_hepatic`. Here neither is needed: gut-wall and hepatic
extraction emerge from an intrinsic clearance and a blood flow. **Oral
bioavailability is an output of this model, not an input to it.**

### The validation gate

The requirement was explicit: do not label the PBPK model validated until its
concentration-time predictions have been tested against suitable independent
clinical observations. That test now exists
(`engine/analysis/pbpk_validation.py`, full write-up in
[VALIDATION.md](VALIDATION.md) §5a):

| | Result |
| --- | --- |
| Held-out AAFE, 66 observed concentrations | **1.185** |
| Within 2-fold | **96.7%** |
| Median absolute error | **14.4%** |
| Cmax AAFE | 1.099 |
| tmax AAFE | 1.521 (the weak spot) |
| Vss predicted vs empirically fitted | 0.479 vs 0.459 L/kg (**1.04-fold**) |

Distribution and absorption are predicted a priori; only clearance is
calibrated, on subjects disjoint from those evaluated. The model reached a
**lower** held-out error than the empirical one-compartment model (1.293) while
estimating **one** parameter from the data instead of three.

### Status deliberately left at `research_only`

The model has cleared the concentration-time gate, and the status was still not
upgraded. Reasons, recorded so the decision can be revisited rather than
re-litigated:

1. **One drug.** Theophylline is freely soluble, highly permeable, neutral,
   low-extraction and minimally bound — close to the easiest case a PBPK model
   can be given. Poulin–Theil is specifically known to fail for
   moderate-to-strong bases, and nothing here tests that.
2. **Plasma only.** The model emits twelve tissue concentrations. One
   observable was tested. Tissue outputs are labelled `UNVALIDATED` in the UI.
3. **Same study.** Out-of-sample across subjects is not out-of-sample across
   studies, laboratories or populations.

A second drug of a different BCS class would justify the upgrade. See P9.

### Known structural weakness this test exposed

Predicted tmax spans 2.18–2.22 h across subjects whose observed tmax spans
1.07–3.55 h. Gastric emptying is a fixed population constant, so every subject
receives the same absorption profile shape. The prediction sits near the middle
of the observed spread (AFE 1.115) but cannot reproduce the spread. This is a
prerequisite for honest population absorption work — see P6.

### Also delivered

- Both absorption-bearing models registered and selectable in Studio.
- `GET /api/validation/pbpk/oral-concentration-time`, running live rather than
  returning a cached claim.
- Evidence workspace → **Oral PBPK validation**: protocol shown *before* the
  accuracy numbers, with caveats given the same visual weight as the headline.
- Multiple dosing **refused** with an explanation for both absorption models,
  because a shared monodisperse particle radius is undefined once a second dose
  arrives mid-dissolution. Returning a number there would be worse than
  returning an error.

## P2 — Drug–drug interactions ⛔ blocked on obtainable data

**Engineering status:** straightforward. Competitive inhibition
(`CLint → CLint / (1 + [I]/Ki)`), mechanism-based inactivation and induction
are small additions to the existing well-stirred hepatic term, and the oral
PBPK model already resolves gut-wall and hepatic extraction separately, which
is what a DDI module needs to distinguish intestinal from hepatic inhibition.

**What blocks it:** the validation data, not the code.

A DDI module is only worth shipping if its predicted AUC and Cmax ratios can be
compared against observed ones for a documented interaction pair. That requires
a victim/perpetrator pair with:

- an observed control and inhibited plasma profile, or at minimum observed
  AUC/Cmax ratios with dispersion, in a retrievable openly licensed source;
- a Ki or k_inact/K_I for the perpetrator from a retrievable source;
- the victim's fraction metabolised by the affected enzyme (fm).

Theophylline is a genuinely attractive victim — it is CYP1A2-dominant, and the
repository already has a validated theophylline model plus the smoking-induction
covariate. Ciprofloxacin and fluvoxamine are both well-documented CYP1A2
inhibitors of it. **What has not been established is whether the quantitative
inputs and the observed ratios are available from a source this project can
actually open.** The paywall-navigation protocol used for the OrBiTo benchmark
(Unpaywall, OpenAlex, PMC, direct fetch) has not yet been run against these
candidates.

**Do not build this before running that check.** A DDI module with an invented
Ki produces plausible-looking interaction predictions that are indistinguishable
from fabricated ones, which is precisely the failure the provenance system
exists to prevent. If the data turns out to be unobtainable, the honest
deliverable is the structural implementation shipped **disabled by default**
with the missing inputs named — the same pattern as `orbito_cases.json`.

## P3 — Advanced absorption and administration ◻ partially built

Already present: pH-dependent solubility (Henderson–Hasselbalch), particle-size
dependence, dissolution of shrinking particles, regional transit, colonic
absorption, solution dosing, precipitation, and now coupling to whole-body
distribution.

Remaining, roughly in order of how cheaply each can be done honestly:

| Item | Blocker |
| --- | --- |
| **Polydisperse particle sizes** | None — engineering only. This is also the prerequisite for lifting the multiple-dosing restriction, since the current shared-radius assumption is what makes a second dose ill-defined. Highest-value next absorption task. |
| **Multiple oral dosing** | Blocked on polydisperse particles above. |
| **Controlled/extended release** | Needs a release-rate model. Honest only with a dissolution profile for a specific named product; otherwise it is a free curve shape fitted to whatever answer is wanted. |
| **Fed state / food effect** | Needs fed-state gastric emptying, volumes, pH and bile-salt concentrations. Mudie 2010 (already cited, open access) covers fasted. A fed-state equivalent has not been located. |
| **Regional permeability** | Needs segment-specific Peff. The canonical human jejunal dataset (Lennernäs, PMID 9548891) was already confirmed paywalled during the absorption work. |
| **Transporter-mediated efflux** | Needs transporter expression and kinetics. Not located. |

IV bolus and infusion already work on the compartmental and PBPK models.

## P4 — Patient-specific physiology ◻ partially built

Already present and individually cited: allometric scaling (CL∝WT^0.75,
V∝WT^1.0), Cockcroft–Gault, CKD-EPI 2021, Du Bois BSA, Janmahasatian fat-free
mass, Devine IBW, a smoking CYP1A2 induction factor and a hepatic-impairment
factor. All are published equations, not arbitrary multipliers.

Not built, and each needs a specific published source before it should be:

- **Paediatric and geriatric physiology.** Needs age-dependent organ volumes,
  perfusion and enzyme ontogeny. The reference physiology currently ships a
  single adult. httk (already a GPL-3 dependency, already parsed
  programmatically) may carry some of this — **this is the most promising lead
  in the whole remaining list and has not yet been checked.**
- **Pregnancy physiology.** Needs gestational-age-dependent parameters.
- **Pharmacogenomics.** Needs genotype-to-CLint factors per enzyme. Plausible
  from CPIC/PharmGKB, licence not yet checked.
- **Disease-state physiology** beyond the existing hepatic factor.

The covariate *magnitudes* that do exist remain unvalidated: no dataset
shipping here pairs covariates with observed concentrations in a way that would
test them. That limitation is already recorded in
[SCIENTIFIC_LIMITATIONS.md](SCIENTIFIC_LIMITATIONS.md).

## P5 — Advanced PD and toxicity ⛔ blocked on obtainable data

Present: sigmoid Emax, four indirect-response variants, effect compartment —
all structurally verified, and **every shipped PD parameter is tagged
`illustrative`**, meaning it is a plausible default chosen to make the software
demonstrable and is explicitly not evidence.

Exposure–toxicity relationships are the single easiest place in this entire
roadmap to produce something that looks authoritative and is fabricated. A
QT-prolongation or hepatotoxicity threshold invented to make a dashboard work
is actively dangerous, because the UI around it is persuasive.

**Requirement before any of this is built:** a retrievable, openly licensed
exposure–response dataset for a specific named adverse effect. Until one is
located, the correct state is the current one — structures present, parameters
labelled as non-evidence, no toxicity claims.

## P6 — Population pharmacometrics ◻ foundations present, NLME not built

Present: Monte Carlo population simulation with log-normal between-subject
variability, correlation matrices with PSD projection, percentile envelopes,
exposure distributions, and a **two-stage** population summary that is
explicitly documented as *not* NLME.

Not built: true non-linear mixed-effects estimation (FOCE/SAEM), visual
predictive checks, bootstrap confidence intervals, covariate model building.

**Honest assessment of feasibility.** Implementing FOCE or SAEM correctly is a
substantial numerical undertaking — the hard parts are the inner-loop
conditional estimation, the gradient/Hessian approximations and convergence
diagnostics, and a subtly wrong implementation produces parameter estimates
that look reasonable and are biased. It is achievable, but it should be scoped
as its own project with its own validation against a published analysis of one
of the shipped datasets (Theoph has been analysed by NLME in the literature
many times, which makes it a genuinely checkable target).

Note the ordering dependency: a population *absorption* model needs
between-subject variability on gastric emptying, which is exactly the gap the
P1 tmax result exposed. That is a smaller and more clearly specified piece of
work than NLME, and it has an immediate measurable payoff — the tmax AAFE of
1.521 is the number it would move.

## P7 — Virtual clinical trials ◻ not built

Depends on P6. The deterministic-seed and reproducibility machinery it needs
already exists (`input_hash`/`record_hash`, verified deterministic reproduction,
fixed random seeds), so this is mostly orchestration on top of a working
population model rather than new science.

The thing to guard against here is presentation, not computation: a simulated
trial with endpoints and a cohort looks exactly like a real one. Any output must
carry the simulated-subject disclaimer as prominently as the result.

## P8 — Experimental data integration ◻ partially built

Present: two shipped observed datasets with full provenance, a dataset loader,
weighted non-linear least squares on log-transformed parameters, asymptotic
standard errors, a condition-number identifiability check, residual
diagnostics, and the unit system that refuses cross-dimension conversion.

Not built: user CSV upload, interactive column mapping, per-upload validation
and unit reconciliation, versioned storage of user datasets.

This is the most purely-engineering item on the list — no external data is
needed, because the data comes from the user. The care required is in
validation on ingest: a silently mis-parsed unit or a mis-mapped column
produces a fit that converges to a wrong answer without complaint. The existing
`UnitError` behaviour (refuse, do not guess) is the right model to extend.

## P9 — Drug and model database ◻ three drugs, deliberately

The library holds theophylline, indomethacin and one explicitly synthetic
non-linear demonstration compound. Every stored parameter carries an origin
tag, between-subject variability where known, and the dataset and subjects it
was fitted from.

**It is small on purpose.** Expanding it means either finding drugs with
openly licensed observed data — which is genuinely scarce — or filling it with
plausible numbers, which would make the provenance system a lie. The
`origin` taxonomy only means something if nothing in the library is invented.

**Highest-value single addition to the entire project.** A second drug of a
different BCS class, with openly licensed observed concentration-time data and
retrievable physicochemistry, would simultaneously:

- unlock the P1 status upgrade (the blocker there is one drug, not one test);
- test Poulin–Theil outside the easy neutral/low-extraction case;
- give the absorption model its first poorly-soluble test, which the OrBiTo
  paywall denied it;
- strengthen every validation claim in the repository at once.

### Candidate datasets — search performed, results below

The Rdatasets index (3,648 entries) was searched and three candidates were
confirmed **fetchable** under the same GPL-2 | GPL-3 licence as the two
datasets already shipped. Each has a specific, named gap. None has been
ingested, because each gap has to be closed first.

| Dataset | Design | Why it is valuable | Gap that blocks it |
| --- | --- | --- | --- |
| **`nlme::Quinidine`** 1,471 rows, 136 subjects | Multiple oral/IV doses, sparse clinical sampling. Columns: time, conc, dose, interval, Age, Height, Weight, Race, Smoke, Ethanol, Heart, Creatinine, **glyco** | **The single most valuable dataset found.** Quinidine is a **base** and is highly bound to alpha-1-acid glycoprotein — exactly the case Poulin–Theil is documented to predict badly, which is the untested weakness of the current distribution model. It also carries the covariate set P4 needs *and* a measured binding-protein concentration, which almost no public dataset has. | Sparse, unbalanced, multiple-dose population design with many blank `conc` rows (dosing records). It cannot be used with the current individual-profile protocol — it needs NLME (**P6**). This dataset is the reason to build P6 rather than an afterthought to it. |
| **`nlme::Cefamandole`** 84 rows, 6 subjects | IV, densely sampled (10 min onward) | Acidic, renally eliminated, low volume of distribution — a genuinely different physicochemical class from theophylline. Being **IV**, it would test the distribution model *without* absorption confounding, which is precisely the gap recorded in P1 ("the intravenous model was not tested"). | **The dataset carries no dose and no body weight** — only Subject, Time, conc. Clearance and volume cannot be scaled without them. The dose is documented in the `nlme` package help rather than the data file; it must be **retrieved and cited, not assumed**. Nothing should be built until it is. |
| **`nlme::Tetracycline1/2`** 40 rows, 5 subjects, 2 formulations | Oral, two formulations | Tetracycline is amphoteric, chelates metals, and is incompletely absorbed — a much harder absorption case than theophylline, and the formulation arm is directly relevant to **P3**. | No dose column, and only five subjects, so a calibrate/hold-out split leaves two or three subjects per side. Underpowered for a validation claim even once the dose is sourced. |

Also noted but rejected: `nlme::Phenobarb` (neonatal — needs the paediatric
physiology that P4 has not built) and `nlme::Remifentanil` (cleared by blood
esterases, so the well-stirred *hepatic* model does not apply and a fair test
would need a different elimination structure).

**Recommended next step, concretely:** retrieve and cite the Cefamandole dose
and body weights from the `nlme` documentation or its cited source (Davidian &
Giltinan). That is a bounded search task, and if it succeeds it unlocks an IV
PBPK validation on an acidic, renally-cleared drug — closing two documented
gaps at once for very little new code, since the IV path through
`PerfusionLimitedPBPK` already exists and the validation harness in
`engine/analysis/pbpk_validation.py` generalises to it.

Still unsearched: PMC open-access articles with tabulated profiles, and the
`PKPDdatasets` ecosystem.

## P10 — Regulatory research workflows ◻ partially built

Present: the Reports workspace generates a complete methods-and-results
document (inputs, per-parameter provenance with origin tags, exposure metrics,
solver diagnostics, independent validation, limitations, references); every run
carries a hash-verified provenance record; reproduction is verified point by
point; there is an audit log.

That covers much of what a model-informed submission actually needs
structurally. What remains is largely document formatting against FDA and EMA
PBPK guidance structure, plus uncertainty/sensitivity sections that can draw on
the existing Morris and Sobol implementations.

**Non-negotiable constraint.** None of this constitutes regulatory acceptance,
compliance or certification, and the software must never imply otherwise merely
because the features exist. The current "not a medical device" banner and the
explicit absence of any HIPAA or GDPR claim must survive this work intact.

## Suggested order for whoever continues

Ranked by value delivered per unit of risk, not by module number:

1. **P9 — source the Cefamandole dose and weights.** The dataset search is
   already done (see P9 for the shortlist and each candidate's specific gap);
   what remains is one bounded retrieval. Success unlocks an IV PBPK validation
   on an acidic, renally-cleared drug and closes two documented gaps at once.
2. **P4 — check whether httk carries paediatric/geriatric physiology.** It is
   already a dependency and already parsed programmatically; this may be a
   cheap, fully cited win.
3. **P3 — polydisperse particle sizes.** Pure engineering, no external data,
   and it lifts the multiple-dosing restriction.
4. **P6 — between-subject variability on gastric emptying.** Small, well
   specified, and directly addresses the measured tmax weakness.
5. **P2 — run the paywall-access protocol on the CYP1A2 DDI candidates** before
   writing any DDI code, so the decision to build or to ship-disabled is made
   on evidence.
6. **P8 — CSV import.** Self-contained engineering.

Deliberately last: P5 and P7, because both are easy to make look convincing and
hard to make true.
